## 1. Мета

Створити повноцінний Android icon pack у стилі класичних об'ємних ілюстрацій Windows XP / Luna початку 2000-х. Пакет має працювати насамперед із Nova Launcher, мати індивідуальні іконки для застосунків користувача, коректні Android package/activity mappings та відтворювану збірку APK.

Це не просто набір логотипів. Це цілісна графічна система з єдиною художньою мовою, широким покриттям застосунків і документацією, що дозволяє іншому ШІ продовжити роботу без повторного пояснення задуму.

## 2. Обов'язкові правила для будь-якого ШІ

1. Головний візуальний еталон — надані користувачем приклади класичних 3D-іконок Windows XP: мальовані об'ємні предмети, виразна перспектива, м'які тіні, відблиски та насичені кольори.
2. Не переходити до flat design, Material Design, мінімалізму, неону чи кіберпанку.
3. Не оформлювати всі програми однаковими квадратними плитками з логотипами.
4. Кожна іконка повинна мати власний силует, композицію та впізнаваний предмет/сюжет.
5. Сучасні бренди (Telegram, WhatsApp, YouTube, ChatGPT тощо) мають залишатися впізнаваними, але бути переосмисленими у візуальній мові Windows XP.
6. Єдність стилю важливіша за кількість. Не додавати слабку іконку лише заради числа.
7. Прозорий фон — бажаний варіант, якщо він пасує конкретній ілюстрації. Не додавати однакові підкладки автоматично.
8. Не вигадувати Android package names або activity names. Брати їх із реального списку застосунків/команд пристрою та перевіряти перед внесенням.
9. Не заявляти про повне покриття, доки не звірено реальні launcher activities з appfilter.xml.
10. Перед перезаписом файлів перевіряти поточний стан Git і зберігати зміни окремими зрозумілими commits.
11. Після кожного етапу оновлювати PROJECT_CONTEXT.md, CHANGELOG.md та ICON_CATALOG.csv.
12. Не комітити паролі, keystore, токени або приватні дані користувача.
13. Не ліцензувати чужі торговельні марки чи ресурси Microsoft як власні. Оригінальні ілюстрації проєкту, код і сторонні матеріали мають бути розмежовані.

## 3. Візуальна специфікація

### Потрібно
- класична 3D-естетика Windows XP / early 2000s;
- мальовані, об'ємні, предметні ілюстрації;
- насичені, але збалансовані кольори;
- м'які тіні, відблиски, градієнти, відчуття матеріалу;
- виразна перспектива та чистий силует;
- достатня читабельність у малому розмірі;
- різні композиції, що відображають призначення застосунків.

### Не потрібно
- flat або монохромних піктограм;
- однакових синіх/скляних квадратних рамок для всіх логотипів;
- сучасного мінімалізму;
- надмірного глянцю, неону чи кіберпанку;
- випадкового змішування різних стилів;
- повторного використання однієї картинки для різних застосунків без обґрунтування.

Користувач окремо зауважив, що в попередній збірці частина іконок втрачала схожість зі зразком. Це ключовий ризик: перед масштабуванням треба провести дизайн-аудит усіх наявних PNG і затвердити єдиний еталон.

## 5. Технічна архітектура

Цільова технологія — Android APK icon pack із ресурсами PNG та XML-мапінгом для Nova Launcher.

Відомі шляхи з попередніх робочих копій:
- app/src/main/AndroidManifest.xml
- app/src/main/res/drawable-nodpi/
- app/src/main/res/xml/appfilter.xml
- app/src/main/res/xml/drawable.xml
- app/src/main/res/values/strings.xml
- app/src/main/res/values/styles.xml
- build.sh
- README_UA.txt

У раннішій версії XML також зустрічався в app/src/main/assets/. Перед змінами перевіряти фактичну структуру, не припускати, що обидва варіанти існують.

Бажаний процес:
- Termux на Android — локальна робота та діагностика;
- GitHub — код, ресурси, документація та історія змін;
- GitHub Actions — автоматична збірка APK;
- GitHub Releases або Actions artifacts — готові APK.

## 6. Історія технічного стану з попередніх логів

Робочі папки Termux:
- ~/xp-iconpack-v2/Windows_XP_Luna_3D_Nova_IconPack
- ~/xp-iconpack/Windows_XP_Nova_IconPack

Відомі проблеми:
1. Пакети android-sdk і zipalign не знаходилися через звичайний pkg install у Termux. Не повторювати цей шлях без перевірки актуального способу встановлення Android SDK.
2. Збірка одного разу не знайшла android.jar.
3. Після часткового оновлення Termux curl падав із помилкою SSL_set_quic_tls_early_data_enabled. Після повного оновлення пакетів curl --version запрацював.
4. Було встановлено, серед іншого, aapt, aapt2, apksigner, d8, openjdk-21 та zip.
5. Компіляція strings.xml зупинялася через unescaped apostrophe in string (апострофи в українських словах на кшталт зв'язку та Прив'язки). Потрібно коректно екранувати апострофи у форматі Android string resources.
6. Автоматичне виявлення launcher activities повертало лише частину списку, тому скрипт використовував резервні прив'язки.

У попередньому логові:
- знайдено launcher-компонентів: 6;
- призначено XP-іконки: 6 із 771 запису;
- Android не повернув повний список launcher-компонентів.

Користувач раніше повідомляв, що встановив і вибрав тестовий icon pack у Nova Launcher. Водночас остання наведена помилка збірки була в strings.xml; успішний результат конкретно тієї останньої спроби не підтверджений. Перед релізом перевірити чисту збірку та фактичне встановлення.

Приклади компонентів, які користувач надсилав у чаті (перед використанням перевірити на пристрої):
- org.telegram.messenger/.TurboIcon
- com.whatsapp.w4b/com.whatsapp.Main
- com.viber.voip/.WelcomeActivity
- com.android.chrome/com.google.android.apps.chrome.Main
- app.revanced22.android.youtube/.revanced_original_1
- com.openai.chatgpt/.MainActivity
- com.teslacoilsw.launcher.prime/android.app.AppDetailsActivity

Останній компонент належить Nova Launcher Prime; не вважати його автоматично звичайною цільовою іконкою.

## 7. Каталог застосунків і приватність

У попередній роботі згадувався файл app-list (1).xml зі списком установлених застосунків та package names. Його потрібно знайти/перевірити перед інвентаризацією. Не вважати кожен package entry launcher-застосунком.

Сирий список застосунків може містити приватну інформацію. Оскільки цей репозиторій зараз публічний, не публікувати сирий app-list (1).xml без окремої згоди користувача. У публічному каталозі залишати лише необхідні назви та mappings; повний приватний інвентар тримати поза публічним репозиторієм або в приватному сховищі.

## 12. Критерії готовності

- усі потрібні користувачу launcher-застосунки враховані;
- кожен має власну відповідну іконку або свідомо вибраний fallback;
- appfilter.xml містить перевірені компоненти;
- усі іконки відповідають єдиній Windows XP 3D стилістиці;
- APK збирається відтворювано, бажано в GitHub Actions;
- APK встановлюється та працює в Nova Launcher;
- оновлення встановлюються поверх попередньої версії з тим самим ключем;
- інший ШІ може продовжити роботу, прочитавши документацію та Git history.

**Головний принцип:** створюємо повноцінний Windows XP Luna 3D icon pack для Android — зі своєю художньою мовою, широким покриттям застосунків, перевіреними прив'язками та відтворюваною збіркою.
